## 如何加一場

1. 把該場做成 JSON(schema 同 `matches/*.json`:`pre_match{handicap,total_line,over_odds_open}`
   + `snapshots[{minute,score,line,over_odds,under_odds}]`),命名 `隊名_日期.json`,放進 `matches/`。
2. 跑批次回測:
   ```bash
   python3 .claude/skills/football-go/calibration/fg_score.py \
     .claude/skills/football-go/calibration/matches/*.json
   ```
3. 把結果與「實際 HT 是否進球」對照,更新下方記分板。

## FG-Score v0.3 公式摘要（現行）

**選場 Gate(不過→SKIP)**:`|讓球| ≥ 0.5` 且 `開盤大小球 ≥ 2.5`
**2.0 硬閘(v0.3 核心)**:破蛋前(仍 0-0)盤口最低線 `< 2.0 → 直接 ABORT`,無視以下分數。
**輔助計分(0~100,僅參考)**:C1 開盤線強度(20)+C2 降盤動能(30)+C3 大球升水到頂循環(25)
+C4 小球升水波(15)+C5 參考規則 223/334/757(10)
**門檻(通過 2.0 硬閘後)**:`raw≥70 STRONG GO` / `50-69 GO` / `30-49 WAIT` / `<30 SKIP`

**版本演進**:
- v0.1 純加權計分 → 被反例完全騙過(reps 85 分卻 0-0)。
- v0.2 改「2.0 軟罰分」(-25/-45) → 仍漏掉 min 線=1.75 的印尼U19。
- v0.3 改「2.0 **硬閘**」→ 6 場 3 正 3 反**完美二分**。

## 🔑 核心發現(v0.3)

**C1–C5 那套(降盤動能/大球升水循環/小球升水波)對「會不會進球」幾乎沒有鑑別力。**
證據:3 個反例 raw = 85/84/78,全部**高於**2 個真進球場(60/51)。將死的 0-0 與將進球的
0-0 在這些指標上型態相同。**唯一在做事的變數 = 破蛋前盤口有沒有跌破 2.0**:
- 3 個有球場最低線 = 2.0 / 3.5 / 2.0(全 ≥2.0)
- 3 個槓龜場最低線 = 1.5 / 1.75 / 1.5(全 <2.0)

**真規則**:選場過後盯大小球線 —— 0-0 時跌破 2.0 → 放棄;撐在 2.0 不破+大球升頂 → 進場。

**最該優先蒐集的「打臉場」(能證偽 2.0 硬閘)**:
1. 盤口**剛好卡 2.0 撐到 HT 卻 0-0** → 若有,2.0 閘出現裂縫。
2. 盤口**跌破 2.0、上半場卻照進** → 若有,硬閘太兇、會錯殺。
